# Melos 8.x + FVM Monorepo Scaffolding Reference & Template Blueprint

This document serves as a comprehensive reference and templating guide for scaffolding modern Dart & Flutter monorepos using **FVM**, **Melos 8.x**, and **Dart Pub Workspaces**. It is designed to serve as input material for authoring a reusable scaffolding skill or automated generator.

---

## 1. Architecture Overview

A modern Flutter/Dart monorepo leverages:
- **FVM (Flutter Version Manager)**: Pins the Flutter and Dart SDK per-project.
- **Dart Pub Workspaces (Dart 3.5+)**: Native dependency sharing across packages without relying on path overrides or symlinks.
- **Melos 8.x**: Orchestrates multi-package lifecycle scripts, versioning, linting, and hybrid testing.
- **Inward Dependency Architecture**: Pure Dart logic at the core, Flutter UI packages depending on pure Dart, and applications depending on both.

```
[ Application / Consumer Packages ]
               │
               ▼
   [ Flutter Feature/UI Packages ] (packages/<pkg>_flutter)
               │
               ▼
     [ Core Pure Dart Packages ]   (packages/<pkg>_dart)
```

## 2. Directory Structure Blueprint

```
<project-root>/
├── .fvm/
│   ├── fvm_config.json                 # Pinned Flutter SDK version
│   └── flutter_sdk -> ...              # SDK symlink generated by fvm
├── .fvmrc                              # FVM shorthand config
├── .gitignore                          # Monorepo ignore rules
├── pubspec.yaml                        # Root workspace & Melos configuration
├── pubspec.lock                        # Unified lockfile for the entire workspace
├── README.md                           # Monorepo documentation & quickstart
├── .gemini/                            # (Optional) Agentic rules & hooks
│   ├── hooks.json                      # Automated format/lint post-tool hooks
│   ├── rules/
│   │   └── melos_fvm.md                # Agent workspace rules
│   └── skills/
│       └── melos-workflow/
│           └── SKILL.md                # Monorepo operational runbook
└── packages/
    ├── <pkg>_dart/                     # Pure Dart package (e.g. ammo_dart)
    │   ├── lib/
    │   │   ├── <pkg>_dart.dart
    │   │   └── src/
    │   ├── test/
    │   │   └── <pkg>_dart_test.dart
    │   └── pubspec.yaml                # Uses `resolution: workspace`
    └── <pkg>_flutter/                  # Flutter package (e.g. ammo_flutter)
        ├── lib/
        │   ├── <pkg>_flutter.dart
        │   └── src/
        ├── test/
        │   └── <pkg>_flutter_test.dart
        └── pubspec.yaml                # Uses `resolution: workspace` & depends on <pkg>_dart
```

### 3.3. Root `pubspec.yaml` (Melos 8.x + Pub Workspaces)

> **Key Note**: Melos 8.x removes the need for a separate `melos.yaml`. All configurations can live directly under the `melos:` key in the root `pubspec.yaml`.

```yaml
name: <project_name>_repo
description: Monorepo workspace for <project_name> Dart and Flutter packages.
repository: https://github.com/<org>/<project_name>-repo
publish_to: none

environment:
  sdk: '>=3.13.0 <4.0.0'

workspace:
  - packages/**

dev_dependencies:
  melos: ^8.9.0
  lints: ^5.0.0

melos:
  sdkPath: .fvm/flutter_sdk

  command:
    version:
      branch: main
      releaseUrl: true
      includeCommitId: true
      linkToCommits: true

    bootstrap:
      environment:
        sdk: '>=3.13.0 <4.0.0'
        flutter: '>=3.47.0'

  scripts:
    lint:all:
      steps:
        - melos analyze
        - format-check
      description: "Run all static analysis and formatting checks."

    analyze:
      run: dart analyze .
      description: "Run dart analyze across all workspace packages."

    format:
      run: dart format .
      description: "Format all Dart files in the workspace."

    format-check:
      run: melos exec dart format . --set-exit-if-changed
      description: "Run dart format checks for all packages."

    test:all:
      run: melos test --no-pub
      description: "Run tests across all packages using appropriate runner (dart test / flutter test)."

    test:dart:
      description: "Run unit tests in pure Dart packages."
      exec:
        command: dart test
        concurrency: 1
      packageFilters:
        scope: <pkg>_dart

    test:flutter:
      description: "Run tests in Flutter packages."
      exec:
        command: flutter test
        concurrency: 1
      packageFilters:
        scope: <pkg>_flutter

    test:select:
      run: melos exec -c 1 -- flutter test
      packageFilters:
        dirExists: test
      description: "Run flutter test for selected packages."

    coverage:
      steps:
        - melos exec -- flutter test --coverage
      packageFilters:
        dirExists: test
      description: "Generate test coverage for packages."

    upgrade:
      run: melos exec flutter pub upgrade
      description: "Run flutter pub upgrade across packages."

    build_runner:
      description: "Execute build_runner code generation in packages that depend on it."
      exec:
        command: dart run build_runner build --delete-conflicting-outputs
        concurrency: 1
      packageFilters:
        dependsOn: build_runner
```

### 3.4. Pure Dart Package Template (`packages/<pkg>_dart/pubspec.yaml`)

```yaml
name: <pkg>_dart
description: Core pure Dart utilities and logic.
version: 0.1.0
publish_to: none

environment:
  sdk: '>=3.13.0 <4.0.0'

resolution: workspace

dev_dependencies:
  test: ^1.25.0
  lints: ^5.0.0
```

---

### 3.5. Flutter Package Template (`packages/<pkg>_flutter/pubspec.yaml`)

```yaml
name: <pkg>_flutter
description: Flutter widgets and utilities built on <pkg>_dart.
version: 0.1.0
publish_to: none

environment:
  sdk: '>=3.13.0 <4.0.0'
  flutter: '>=3.47.0'

resolution: workspace

dependencies:
  flutter:
    sdk: flutter
  # Inward workspace dependency resolved automatically:
  <pkg>_dart:

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^5.0.0
```

## 4. Step-by-Step Scaffolding Procedure

To scaffold a new repository using this pattern:

```bash
# Step 1: Create Monorepo Root Directory & Git Repository
mkdir my_project_repo
cd my_project_repo
git init

# Step 2: Initialize FVM
# Create .fvmrc with desired channel (e.g. "stable")
echo '{"flutter": "stable"}' > .fvmrc
fvm install
fvm use stable

# Step 3: Create Workspace Directory Structure
mkdir packages
mkdir packages/my_project_dart
mkdir packages/my_project_flutter

# Step 4: Add Root pubspec.yaml & .gitignore
# Write root pubspec.yaml with `workspace: [packages/**]` and `melos:` configuration
# Write .gitignore

# Step 5: Activate Melos Inside FVM Environment
fvm dart pub global activate melos

# Step 6: Create Child Package Pubspecs & Boilerplate
# Write packages/my_project_dart/pubspec.yaml (with resolution: workspace)
# Write packages/my_project_flutter/pubspec.yaml (with resolution: workspace and dependency on my_project_dart)

# Step 7: Resolve All Dependencies Across the Workspace
fvm dart pub get

# Step 8: Verify Workspace Setup
melos run lint:all
melos run test:all
```

## 5. Critical Rules & Pitfalls Handled

1. **Native Pub Workspaces (`resolution: workspace`)**:
   - Child packages do NOT specify path overrides for sibling packages.
   - Simply declaring `<pkg>_dart:` inside `dependencies:` resolves directly to the sibling package within the workspace.
2. **`melos test --no-pub` for Hybrid Repositories**:
   - `dart test` cannot execute tests containing `import 'package:flutter/...'` because `dart:ui` is missing outside the Flutter test harness.
   - `melos test` intelligently selects `dart test` for Dart packages and `flutter test` for Flutter packages.
3. **Melos 8 Script Rules (`run:` vs `exec:`)**:
   - `run:` executes once at root.
   - `exec:` loops over filtered packages.
   - Never combine `run:` and `exec:` under the same script identifier.
4. **Output Concurrency in Tests**:
   - Always specify `concurrency: 1` on `exec:` test scripts to avoid mangled terminal outputs.
5. **SDK Pinning with Melos**:
   - Always declare `melos: sdkPath: .fvm/flutter_sdk` to ensure Melos uses the same pinned Flutter/Dart version as developer workstations and CI runners.
